# Доход TravelTribe

Цель — установить, где возникло человеческое коммерческое действие, во что оно
превратилось и сколько зрелых денег принесло после отмен.

## Источники истины

Перед анализом прочитай [`MONETIZATION-2026.md`](../../../MONETIZATION-2026.md)
и денежные правила [`CLAUDE.md`](../../../CLAUDE.md). Используй Метрику для
человеческих целей, официальный API Travelpayouts для действий и финансовых
статусов, GSC/Вебмастер для поискового источника. `.github/scripts/seo_pulse.py`
и `scripts/monetization-report.mjs` — стартовые инструменты, не доказательство
сами по себе.

## Рабочий процесс

1. Зафиксируй текущую дату, часовой пояс отчёта, окно и вопрос: здоровье пути,
   конкретное действие, сравнение страниц или эксперимент.
2. Сними по одинаковому окну:
   - органические визиты и человеческие outbound-цели из Метрики;
   - клики, действия, цену, комиссию и статус из Travelpayouts;
   - страницу, канал, устройство и доступные `sub_id`/`cta_id`/click id.
3. Разделяй статусы:
   - `processing` — бронь в обработке и только потенциальная комиссия;
   - `approved`, `confirmed`, `paid` — доход согласно действующему контракту;
   - `cancelled`, `rejected` и возвраты — не доход.
   Если программа использует иной словарь, сначала сопоставь его с официальной
   документацией и сохрани исходный статус.
4. Восстанови путь `поисковый запрос → landing → CTA → партнёр → действие`.
   Не утверждай точный CTA или клик без joinable идентификатора. Cookie и
   last-click могут атрибутировать покупку другого маршрута или товара.
5. Считай по страницам и намерениям: outbound/visit, processing/goal,
   confirmed/goal, отмены и чистая комиссия на 1000 органических визитов.
   Показывай числитель, знаменатель и размер выборки.
6. Сравнивай варианты только по зрелым эквивалентным когортам. Один дорогой
   pending-заказ — доказательство рабочего пути, но не победа варианта и не
   прогноз RPM.
7. Найди причину на уровне трафика, предложения, клика, атрибуции, статуса или
   отчёта. Сначала проверь измерение: неверное поле API или потерянный `sub_id`
   может создать ложный ноль.
8. Для изменения кода сначала добавь RED-регрессию, затем исправление и GREEN.
   После выпуска проверь API и live-путь повторно. При запросе только на анализ
   ничего не меняй.

## Результат

Первой строкой ответь, сколько денег подтверждено, сколько лишь потенциально и
какой статус у действий. Затем объясни где, почему, насколько вывод надёжен и
что измерять дальше. Не называй pending заработком.

При изменении skill используй кейсы из
[`references/evaluation-cases.json`](references/evaluation-cases.json); в
обычной денежной задаче их не загружай.

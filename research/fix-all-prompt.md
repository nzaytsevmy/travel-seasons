# Промт: починить однотипность и доделать всё, что открыла пересборка семантики

Составлен 29.08.2026 по указанию Никиты «делай промт для починки и делания
всего». Причина формата — урок визовой страницы: «готово» решалось впечатлением,
а не списком. Здесь список, каждая строка закрывается числом или сырым выводом.

## Что чиним и почему (диагнозы, всё замерено)

1. **Три четверти сайта меняют от месяца две строки.** Сборы в дорогу (963 стр.)
   и поездки по месяцам (900 стр.): у худших пар 44% дословно совпадающих
   предложений. Корень: настоящая помесячная погода есть у 16 стран из 74,
   остальные живут на девяти погодных наборах на весь мир, где тропический год
   делится надвое. Список вещей у Гоа в марте и ноябре одинаков.
   ⛔ Удалять эти страницы НЕЛЬЗЯ — замер 04.08.2026: они лидеры роста в Google.
   Чинить = дать настоящие данные.
2. **Ссылками указываем не на то.** Сборы на море получают 356 внутренних
   ссылок, Рица 12, грузинская страховка 10, Занзибар 8. Все страницы с нулевым
   охватом — внизу списка.
3. **Из методики не сделано три вещи:** сравнение верхних запросов тем с нашими
   реальными переходами (дыры ядра считаются списком); окно 16 месяцев вместо
   недельных сравнений; проверка «есть ли на странице собственные данные» вместо
   «чем страницы отличаются».
4. **Выдача не смотрена у 4 направлений из 13:** Китай, Япония, Шри-Ланка, Бали.
5. **Заявка с 18 коммитами пересборки не влита** — ждёт зелёных прогонов.

## ⛔ Предохранители (нарушение любого = стоп)

- **Погоду НЕ выдумывать.** Каждое число — из климатических норм с источником
  (climate-data.org / climatestotravel.com / weatherspark / WMO), как у
  существующих 16 стран. Город замера называется. Не нашёл источник — страна
  пропускается и называется пропущенной.
- Правка файла погоды = датированная фактура → бампнуть DATA_UPDATED в meta.js.
- Новым страницам FAQPage не ставить; существующую разметку не срывать.
- После смены любого факта — grep по репо (llms.txt включая).
- Гейт перед коммитом стандартный: сборка, инварианты, визуал на изменённых
  типах. Слияние по зелёным — разрешено, публикация наружу — нет.
- Число заходов замера скорости не снижать; пороги не двигать.
- Чужие правки в общем каталоге не трогать; работа в ~/tt-home.

## Этапы

**Этап 0 — влить заявку.** Дождаться прогонов, влить по зелёным. Красное —
разобрать, не двигая порогов.

**Этап 1 — погода волны 1: Египет, Южная Корея, Гоа, Черногория.**
Выбор обоснован: Египет и Корея — лидеры роста Google без данных; Гоа и
Черногория — проверенно открытая выдача без данных. 48 страниц.
Для каждой страны: город замера, 12 месяцев температура + осадки/дни, источник.
Формат — как у 16 существующих в файле помесячной погоды.

**Этап 2 — бакет из данных, а не из руки.** Там, где настоящая погода есть,
погодный набор выводится ИЗ неё (порогами по температуре и осадкам), а не из
статичной таблицы регионов. Пороги написать явно в коде с комментарием. Итог:
у страны с данными соседние месяцы с разной погодой получают разные наборы
вещей. Ручная таблица остаётся запасным путём для стран без данных.

**Этап 3 — перезамер однотипности.** Прогнать scripts/odnotipnost.py до и после
на тех же парах. Приёмка не «стало красивее», а число: доля совпадений у пар
волны 1 падает. Если не падает — этап 2 не сработал, разбираться, не рапортовать.

**Этап 4 — проверка переписывается на «собственные данные».** В
scripts/odnotipnost.py добавить второй замер: сколько на странице
месяце-специфичных фактов (температура месяца, осадки, цена месяца, события
месяца). Страница без единого — в красный список. Это и есть проверка асессора
«та же беда на соседних страницах».

**Этап 5 — перелинковка сирот.** Дальние дорогие страницы (Занзибар, страховки,
Непал, Сейшелы, Маврикий, ЮАР) получают входящие ссылки из хабов и сезонных
страниц — контекстные, не списком внизу. Приёмка: счёт входящих по сборке до и
после, у каждого сироты рост.

**Этап 6 — дыры ядра списком.** Взять верхние запросы наших тем (Вебмастер) и
сравнить с тем, по чему реально получаем переходы; разница = список тем в ядро
с датой. Плюс: в понедельничный отчёт — сравнение «три месяца год к году»
вместо недельного окна (окно 16 месяцев).

**Этап 7 — выдача четырёх оставшихся направлений.** Китай, Япония, Шри-Ланка,
Бали — глазами, вердикт в ядро, страница-артефакт обновляется.

**Этап 8 — волна 2 погоды.** Остальные страны без данных, приоритет по
входящему трафику из отчётов, партиями по 6–8 стран с теми же предохранителями.
Это длинный хвост — честно вести счёт «сделано X из 58».

# Интеграция предложения — не применено к репозиторию

Не переносить только null-квоты в рабочую конфигурацию: старый news-cap воспримет null как нулевой потолок и удалит кандидатов. Режим, скрипт, потребители и тесты должны меняться согласованно.

## Требуемые изменения

В существующем `news/config.json` сохранить все остальные поля, включая allowedSourceDomains, radar и paused. Добавить `selectionMode: "editorial"`; targetPerDay и maxPerDay сделать null только одновременно с заменой всех использующих их потребителей. minScore оставить 3.

Предлагаемая замена `scripts/news-cap.mjs` входит в пакет. Она ничего не удаляет и не объявляет готовность к публикации. Штатный source-gate и независимая редактура остаются обязательными.

Синхронизировать `NEWS-SELECTION-PROMPT.md`, `GROWTH-CONTROL.md`, `news/RUBRIC.md`, действующие указания `CLAUDE.md`, все связанные контрактные тесты и все потребители полей. Полный поиск провести локальным git grep; удалённый поиск дал неполный результат.

## Дата ленты

Добавить helper `src/data/news-feed-check.mjs`, затем в `src/pages/novosti/index.astro`:

```js
import { latestFeedCheck } from '../../data/news-feed-check.mjs';
// Вместо даты первого элемента:
const lastChecked = latestFeedCheck(fresh);
```

Это исправляет агрегирование существующего checked, но не решает общий вопрос dateModified. Проверка без изменения содержания сама по себе не означает новое содержание страницы; семантику дат следует проверить отдельно до SEO-релиза.

## Проверки и границы

В отдельном наборе `node --test tests/editorial-proposal.test.mjs` проверено 21 поведение. CLI против настоящего news-gate, интеграция с другими потребителями, сборка Astro и тесты сайта не запускались. Изменения кода/конфигурации требуют штатного exact-HEAD preflight и полного применимого CI до merge, затем подтверждённой выкладки и проверки живых страниц.

Файлы из drafts не предназначены для прямого импорта в коллекцию. В них нет финальной редакторской подписи, лицензированной фотографии и публикационных метаданных. Не выдумывать эти поля при интеграции.

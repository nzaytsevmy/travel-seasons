**🟠 P2 — новая:**
- `visa-trip-mid-filter-includes-cheap` — на `/visa/` чип «100–200 тыс.» (фильтр по
  цене поездки, новый блок) обещает диапазон, а по факту показывает всё «до 200 тыс.»
  без нижней границы (`index.astro:56,755,799`, везде условие `tr <= 200000`) — то
  есть включает и то, что уже показывает чип «до 100 тыс.». Комментарий в самом коде
  подтверждает: замысел действительно кумулятивный «до 100 / до 200», баг только в

  63 000 ₽» при активном фильтре «100–200 тыс.» — прямое противоречие для читателя.
  Скрин `radar/assets/visa-trip-mid-filter-includes-cheap.png`. Фикс одной строкой:
  текст чипа `:324` → «До 200 тыс.» (совпадёт с реальным и, похоже, задуманным
  поведением). Настоящий диапазон — отдельное решение владельца, меняет то, что
  фильтр показывает сегодня.

## Проверено и чисто

- **`calculator-touch-target-40px` — ЗАКРЫТ.** Живьём @360px: все 5 кнопок
  сегмент-контрола (Эконом/Комфорт/Люкс, ₽/$) — ровно 44px через
  `getBoundingClientRect`. Базовое правило теперь `min-height:32px` с явным
  комментарием «на телефоне 44px — см. @640», мобильный override даёт 44px
  (`calculator.astro:978-995,1626`). Держался открытым с W27 по W35 — исправлено
  где-то в потоке из ~230 коммитов между W35 и этим прогоном.
- **`cards-virtualcard-cta-no-erid` — переведён в `wontfix`.** В коде появился явный
  комментарий владельца: «Метки erid НЕТ и не будет: партнёр её не выдаёт (решение
  Никиты 24.08.2026 — тему закрыть и в отчётах больше не поднимать)»
  (`affiliate.js:34-37`). У нового партнёра youtravel (`:40-43`) — та же формулировка,
  тот же закрытый вопрос; отдельной находкой не заводился.
- **SwissHeader — мега-меню на `<details>` (новое, +253 строки).** Полная проверка
  открытия/закрытия на живом сайте:
  - @360 (мобайл): бургер открывает меню, клик по `<summary>` раскрывает подсписок,
    4/4 ссылок реально видимы (`offsetParent`), высота ссылок 52px (>44 канон).
  - @1280 (десктоп): наведение открывает подсписок через реальное изменение `open`
    (не просто CSS `:hover`) — 4/4 ссылок видимы, кликабельны (`elementFromPoint`
    возвращает саму ссылку).
  - Закрытие проверено трижды: `mouseleave` (таймер 180мс), `Escape`, клик мимо шапки —
    во всех трёх `open` корректно становится `false`.
  - **Ловушка методики, стоит записать для следующих прогонов.** `.nav ul .sub{display:flex}`
    — безусловное правило, которое по specificity перебивает `details:not([open])
    > *{display:none}` из UA-стиля. Naïve-проверка `offsetParent !== null` после
    закрытия даёт **false positive** («ещё видимо» — 4/4 после Escape) — потому что
    геометрия элемента остаётся ненулевой. Реальная проверка (скриншот +
    `document.elementFromPoint` в центре бывшего меню) показала: после закрытия там
    рендерится `.veil` (тёмная плашка поверх hero-фото), сама ссылка не получает
    клики. Chromium прячет закрытый `<details>`-контент через внутренний механизм
    (обёртка вокруг `::details-content`), не сводимый к обычным CSS-свойствам на
    самом ребёнке — `getComputedStyle` на `.sub` показывает `display:flex;
    opacity:1; visibility:visible` даже когда контент реально не рисуется. Меню
    работает верно; вывод — для будущих прогонов на `<details>`-паттернах
    `offsetParent`/`getComputedStyle` одних недостаточно, нужен
    `elementFromPoint`/скриншот.
- **`DestinationTabs` (новый компонент, вкладки хаб/когда/виза/сборы/сравнить)** —
  проверено на `/turkey/`, `/visa/turkey/`, `/packing/turkey/`,
  `/trips/september/turkey/`: @360 и @1280, 5 вкладок, все `min-height` ровно 44px,
  0 горизонтального переполнения страницы.
- **Фильтры `/visa/` (функциональная логика, помимо находки выше)** — живьём @360 и
  @1280: клик «Без визы» → 45/77 видимых, счётчик страницы синхронен; комбинация
  «Без визы» + «Бесплатно» → 37/77, тоже синхронно; «Сбросить» возвращает 77/77 и
  `aria-pressed` на «Все»; поиск «япон» → 1 карточка (Япония), кнопка очистки
  появляется и работает; сортировка «Дешёвая виза» переключает `aria-pressed`. Расхождений
  видимого счёта и текста счётчика не найдено нигде, кроме находки выше.
- **`/compare/` — выбор двух стран через `<select>`** (компонент не менялся
  функционально) — смена обеих стран не роняет страницу, живой пересчёт таблицы отрабатывает.
- **`packing-filter-hidden-not-applied` (P1, W27) держится.** `/packing/egypt/june/`

- **Геометрия на живом проде**, 12 URL × 2 viewport (`/`, `/visa/`, `/trips/`,

  `/packing/turkey/`, `/trips/september/turkey/`) — `document.documentElement

- **Консистентность чисел** — «70+ направлений/стран» держится как future-proof

  `DIRECTIONS.length` сейчас 77 (было 74 на W35).

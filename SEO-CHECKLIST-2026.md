## A. Технический фундамент (Google + Яндекс)
- [ ] HTTPS на всех URL, без mixed content
- [ ] Canonical на каждой странице, self-referential, абсолютный URL
- [ ] robots: `index, follow, max-image-preview:large, max-snippet:-1`; noindex только где надо
- [ ] sitemap: только canonical-URL со статусом 200, **реальный lastmod** (не дата сборки), сегментация по типам
- [ ] AI-боты НЕ заблокированы в robots.txt: GPTBot, ClaudeBot, PerplexityBot, Google-Extended (решение осознанное)
- [ ] Краулабельные ссылки (`<a href>`, не JS-onclick), нет orphan-страниц
- [ ] Чистые короткие URL, без параметров мусора
- [ ] Нет 4xx/5xx на внутренних ссылках; битые ссылки = 0

## B. On-page / контент (Google Helpful Content + утечка 2024 + Яндекс)
- [ ] Оригинальная информация/анализ/опыт, а не пересказ источников; глубина > поверхностного обзора (Google «Helpful Content»)
- [ ] **Ключ в начале `<title>`** (≤60) — `titlematchScore` из утечки явно меряет соответствие title↔запрос; H1, первый абзац, alt, анкоры
- [ ] **Критичный контент — в начало страницы** (Mustang усекает документ по токен-лимиту — утечка)
- [ ] Один H1, иерархия H2/H3 = под-вопросы; meta description ≤155, уникальна, с интентом
- [ ] Изображения: descriptive alt, lazy кроме hero, webp (НЕ avif — [[feedback_safari_avif_bug]])
- [ ] Внутренняя перелинковка 3+ контекстных (триангуляция hub↔visa↔seasons↔blog); анкор descriptive, не «тут»
- [ ] **Тематическая узость страницы** — не уводить от темы сайта (`siteRadius` из утечки штрафует off-topic дрейф)
- [ ] ❌ Red flags (Google, прямой запрет): контент «под трафик», масс-генерация, авто-AI без ценности, под word-count, **искусственное обновление даты без правок контента**, ниша только ради трафика

## C. E-E-A-T / авторство (Google QRG ред. 09.2025 + утечка 2024 + Яндекс YMYL)
- [ ] **Trust — приоритет №1 из E-E-A-T** (QRG): достоверность важнее экспертности; Experience (личный опыт) для travel — сильнейший сигнал
- [ ] Видимый автор + дата: byline «Никита Зайцев · @traveltriberu · данные актуальны на DD MMM YYYY»
- [ ] Author/Person schema, **консистентная entity** автора на всех материалах (утечка: Google явно меряет `isAuthor`/совпадение автора-сущности)
- [ ] About-страница отвечает на **Кто / Как / Почему** создан контент (QRG-линза); раскрытие AI-использования если есть
- [ ] **YMYL расширен (QRG 09.2025):** деньги/здоровье + теперь общество/госуслуги/выборы. Visa/деньги-страницы = повышенный EEAT: ссылка на первоисточник (МИД РФ/посольство/банк), дисклеймер актуальности
- [ ] Цифры конкретны и датированы; дата консистентна в title/URL/Schema (утечка: конфликт дат = сигнал низкого качества)
- [ ] Самопроверка QRG: «забукмаркил бы / порекомендовал? уровень печатного справочника?»

## F. Яндекс-специфика (часто игнорируют Google-чеклисты)
- [ ] **Поведенческие — главный вес у Яндекса** (с 2011): CTR сниппета, dwell time, низкий возврат к выдаче. Алгоритм **«Тайфун» 2025** встроил антифрод ПФ прямо в формулу — накрутка = подъём фильтра, никогда не накручивать
- [ ] **ИКС** (Индекс качества сайта) растить органикой: полезность, доверие, бренд. Метрика **«Проксима»** непрерывно сканирует авторитетность/качество
- [ ] Брендовые/прямые визиты (Telegram-канал → сайт) и узнаваемость = сильный сигнал Яндекса
- [ ] **Баден-Баден** (текстовая переоптимизация) — не спамить ключами, естественный язык; **Минусинск** — ссылочный спам; **АГС** — малополезные страницы

- [ ] Без агрессивной рекламы/попапов, перекрывающих контент
- [ ] Ссылочный спам = 0 (биржевые ссылки = риск Минусинска); подключены Яндекс.Вебмастер + GSC, 0 ошибок

## I. Стратегия — топикальная авторитетность (канон 2026)
Google Core Update март-2026 закрепил: сайт с 20 связанными статьями по теме обыгрывает сайт с одним мегагайдом.
- [ ] **Топикальная карта:** seed-тема → 3–5 кластеров → 6–12 связанных страниц на кластер (pillar → cluster → support: определения/FAQ)
- [ ] Pillar = исчерпывающий хаб с исходящими на все cluster-страницы; cluster узко и глубоко (1500–2500 слов), линк назад на pillar
- [ ] **Покрытие 4 интентов** на тему: информационный / коммерческий / транзакционный / нишевый-контекстный; вопросы из People Also Ask, Reddit, форумов
- [ ] Анти-каннибализация: одна страница = один интент; pillar и cluster не конкурируют
- [ ] Entity SEO: единый Site Knowledge Graph — сущности (страны, визы, автор, бренд) и их связи консистентны во всём графе schema
- [ ] **Каденс важнее всплеска:** 1–2 cluster-страницы/нед стабильно 6 мес > 20 страниц за 2 нед и тишина
- [ ] Освежать pillar каждые 60–90 дней реальными данными (не косметическая смена даты — Google флагует); квартально ревизия слабых cluster
- [ ] Аудит внутренних ссылок каждые 60–90 дней при росте контента

# Редакционный канон из шести первичек (сведено 12.08.2026)

Источники — только документы, написанные людьми и проверенные десятилетиями, ноль маркетинга: руководство Google для живых асессоров (редакция 11.09.2025, 182 стр., читали сам PDF), правила качества Яндекса (помощь Вебмастера, живьём), контент-стандарт правительства Британии (GDS), исследования чтения лаборатории Нильсена (айтрекинг, 500+ участников), редакционные правила BBC (Accuracy §3, Impartiality §2, стайлгайд), справочник Reuters (Standards & Values + сорсинг). Ниже — только дельта к нашим канонам: что добавляем и какие конфликты как решены.

## Достоверность (BBC + Reuters + асессоры Google)

- **У каждого числа — источник и дата в пределах одного-двух предложений.** Не «в статье есть ссылки», а рядом с цифрой (Reuters: источник у каждого утверждения, в первых двух абзацах — источник истории).
- **Валютная сумма — с конвертацией в рубли при первом упоминании** (BBC Currencies). AUD 250 без «≈ 14 700 ₽» — недоделка.
- **Непроверенное помечать прямо** («официальных разъяснений нет», «источники расходятся») и писать также то, чего НЕ знаем (BBC 3.4.6, Reuters). Пропуск существенной оговорки = неточность (BBC 3.4.19).
- **Смысловая правка — с видимой пометкой в тексте.** Образец уже есть в статье о грузинской страховке: «Раньше здесь было написано X. Это была ошибка — я её исправил». Теперь это норма, не подвиг (BBC 3.4.34–36).
- **Числовой само-чек перед публикацией:** компоненты сходятся с итогом, проценты дают 100, конвертации пересчитываются в обе стороны, миллионы не спутаны с миллиардами (Reuters).
- **Вторая пара глаз обязательна для новой статьи** — адверсарный критик в чистом контексте до публикации (Reuters «second pair of eyes»; у нас уже практика, теперь правило). Находки чинить до выкладки.
- **Тест на копию:** асессоров Google прямо учат гуглить фразы страницы в кавычках (§4.6.7). Перед публикацией новой статьи — проверить 2–3 своих ключевых формулировки: совпадения дословно = переписать.
- **Устаревшая цена — не косметика, а нарушение.** Яндекс называет «неточную информацию, из-за которой можно потерять деньги», недобросовестным действием с санкциями; асессоры Google запрещают высокие оценки при устаревших датозависимых фактах (§18.0). Даты индексаций сборов (Австралия — каждое 1 июля) — в календарь ревизии.

## Структура и внимание (Нильсен + GDS + асессоры)

- **Читают ~20% слов страницы** (потолок 28%); всё, что не в заголовках, первых словах абзацев, жирном и списках, — считать невидимым. Ключевой факт, спрятанный в середине длинного абзаца, не существует.
- **Вода перед сутью — прямой триггер низкой оценки** (асессоры §5.2.2: filler перед полезным = Low; «самый полезный контент — вверху»). Наш answer-first этим подтверждён снаружи.
- **Подзаголовки — «слоёный пирог»:** прочитанные подряд, одни H2 должны пересказывать статью. Проверка при вычитке: прочитай только H2 — понятна ли статья.
- **Первые два слова заголовка и абзаца несут смысл** (глаз видит ~11 знаков в списке). Не «Немного о том, как…», а «Сбор вырос…».
- **Абзац ≤5 предложений (GDS), предложение — ориентир 15–20 слов, длиннее 25 — кандидат на разбивку.** Наши медианы 9–16 — держать.
- **Оглавление длинной статье — вверху в теле** (правую колонку не видят). У нас уже так.
- **Заголовок не обещает больше текста.** Преувеличение = Low, «крайнее» преувеличение = Lowest у асессоров (§4.0/5.2). «!!!», КАПС-слова, «шок» — под запретом гейта.

## Конфликты первичек с нашим каноном — решения

- **GDS запрещает вопросные H2 и FAQ-формат — оставляем наши вопросы.** GDS писан для госзадач без поисковой конкуренции; у нас вопросные H2 и FAQ-разметка дают замеренную цитируемость в нейроответах (×2,8) и попадание в подсказки. Берём от GDS только требование информативных первых слов вопроса.
- **BBC «предложение не начинается с цифры» — не берём:** англоязычная типографская конвенция; в русском информационном стиле цифра в начале — сила, а не ошибка.
- **BBC «числа один–девять словами» — не берём** по той же причине: наш канон — конкретика цифрами.

## Вечнозелёность (BBC-даты, адаптировано)

- В статьях блога запрещены относительные даты: «вчера», «на днях», «на этой неделе», «в прошлом месяце» — через месяц это враньё. Только абсолютные: «в июле 2026», «12 августа 2026». Гейт в тестах контента.

# Канон Яндекса: ЭПОС и ответы Алисы AI (первоисточник, снято 12.08.2026)

Прочитаны страницы помощи Вебмастера живьём: «Какие аспекты влияют на ранжирование в Поиске и попадание в ответы Алисы AI», «Как формируются ответы Алисы AI», «Видимость сайта в Алисе AI», «Отличия качественного сайта от некачественного». Это официальная позиция Яндекса, а не разбор SEO-блога — наш прежний источник по Яндексу был именно разбором.

## ЭПОС — рамка, которой у нас не было

Яндекс сгруппировал факторы качества в четыре аспекта и дал к каждому вопрос для самопроверки. Прогонять статью по ним перед публикацией:

- **Экспертность** — «доверяю ли я, находясь в роли обычного пользователя, этому автору и сайту?» Требуют рассказать об авторе: специализация, подтверждённый опыт, репутация. Прямо сказано: избегать публикации непроверенного контента, опираться на практический опыт.
- **Полезность** — «помогла ли страница пользователю решить его задачу?» Мерить конверсию в решение задачи; для контентных проектов Яндекс сам называет метрики: прочтение до конца, глубина просмотра, активное действие.
- **Оригинальность** — «создаю ли я контент, который трудно или невозможно получить где-то ещё?» Ключевая формулировка: уникальность текста сама по себе ничего не гарантирует; нейросети «не должны подменять автора, лишая текст смысловой новизны, авторского стиля и экспертизы»; цитирование чужого допустимо — ценность создаёт авторская часть.
- **Содержательность** — «дал ли я необходимый, конкретный и практически полезный контент в лаконичной форме?» Дословно: «не каждый длинный текст — содержательный», «маскировка под эксперта не стоит усилий». Требуют раскрывать преимущества И недостатки вариантов.

**Что это меняет у нас.** Наш канон был заточен под Google-рамку E-E-A-T; ЭПОС добавляет два требования, которых там нет: показывать недостатки вариантов, а не только плюсы, и мерить полезность прочтением до конца, а не показами.

## Как устроены ответы Алисы AI (официально)

- Алиса **не воспроизводит контент дословно**, кроме прямой речи, и опирается на источники, которые **высоко ранжируются в поиске**. Вывод: попасть в нейроответ, не будучи в топе, нельзя — это подтверждает наше правило «ниже топ-6 запрос пропускать».
- Ответ **делится на смысловые блоки**: краткий ответ в одно-два предложения, затем последовательные параграфы по подвопросам. Ссылки расставляются **по смыслу параграфов, а не по ранжированию**, одна страница может быть источником нескольких параграфов.
- Отбор источников идёт по тем же четырём аспектам ЭПОС.
- Ответ пересобирается каждый раз заново, **состав источников меняется в течение дня** — разовый замер «нас не цитируют» ничего не доказывает, нужен ряд.

**Практическое следствие для структуры статьи:** писать так, чтобы каждый раздел был самодостаточным ответом на подвопрос — Алиса цитирует параграфами, а не статьями. Это усиливает наше правило «H2 = вопрос, ответ сразу под ним»: теперь оно подтверждено описанием механики, а не только замерами CTR.

## Инструмент, которым мы не пользовались

В Вебмастере есть раздел **«Видимость сайта в Алисе AI»**: доля упоминаний сайта среди источников (метрика Share of Voice), динамика за 3 месяца с недельным обновлением, примеры запросов с нашими и чужими страницами, список сайтов-соседей по нейровыдаче. Данные собираются только по запросам, где сайт уже высоко в выдаче.

⚠️ **В API Вебмастера этого метода нет** — перепроверено 12.08.2026 напрямую: `alice-answers`, `generative-answers`, `sov` → 404. Снимать только руками в интерфейсе; напоминание об этом уже стоит в ежемесячной ревизии отчёта (проверил перед тем, как заводить дубль — оно там было). Что добавляем к нему смыслом: падение доли — сигнал, что контент устарел или конкуренты обошли, и повод сверить свои страницы с чужими по тем же запросам прямо в инструменте.

## Прямые запреты Яндекса, которые стоит помнить дословно

Из списка нарушений: **«намеренно обманывает ожидания пользователей неточной или искажённой информацией, из-за которой можно потерять деньги»** — под это подпадает наша устаревшая цена визы, а не только злой умысел. Плюс: SEO-тексты «для манипуляции», ссылки «по чьей-либо просьбе», привлечение по нерелевантным запросам, малополезный контент.

# Живые эталоны (сведено 12.08.2026 — полный разбор в RESEARCH-BENCHMARKS.md)

- Ответ, заголовок и даты — в первом телефонном экране; обложка не выше 30% экрана на мобиле.
- Денежная точка в капсуле ответа — норма для всех гайдов (капсула + тело + финал = три точки канона).
- У денежной кнопки словами: куда ведёт и что там («оплата из России», «полис в PDF») — рядом, не в подвале.
- Порядок секций гайда сверять с путём путешественника: сориентируйся → доберись → займись → потрать → выживи → уважай → куда дальше.
- Микроистория из опыта внутри совета — приём доверия №1 (Стивз); брать из канала.
- Первый экран телефона: заголовок, обе даты и начало ответа. Ни обложка, ни оглавление, ни плашка согласия не имеют права их выталкивать — проверять живой страницей, а не вёрсткой в голове.
- Навигация по статье (оглавление) на телефоне свёрнута: ответ важнее списка ссылок.
- Анти-образцы: врезки-продажи в середине чтения, дедлайн-давление, «обновлено» без датирования цифр, хабы на 150 ссылок.

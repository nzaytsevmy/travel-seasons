# Тесты и визуальный прогон — выученные грабли

Перенесено из корневого `CLAUDE.md` 08.09.2026 без изменения текста. Подгружается само, когда правишь файлы из `paths` в шапке; пути в тексте — от корня репозитория.

- Playwright visual baseline исторически устаревал — не принимать фейлы нетронутых страниц
  за свой регресс без A/B на чистом HEAD. blog-japan fullPage флейкует под параллелью (pre-existing).
- Хвоста «часть HTML не сжимается» больше нет: сжатие HTML выключено 19.08.2026. Калькулятор: LCP ~2.7 с
  (JS-heavy) при пороге 2,5 с — по web.dev это «требует улучшения», а не «не блокер»; страница денежная,
  долг открыт. Не выдавать за свежий регресс, но и не списывать.
- Гейт `tests/content-invariants.spec.ts` (скан `dist/`, без baseline) ловит классы багов на ВСЕХ постах,
  даже вне visual-PAGES: «от <не-цифра>», видимая метка «реклама». Новый пост страхует ОН, не скриншот-список.
- Визуал-тест догружает lazy-картинки + `decode()` ДО `toHaveScreenshot` (детерминизм fullPage) —
  раньше длинные посты флейкали из-за догрузки во время capture (это и был «pre-existing флейк»).
- Playwright-spec использует `test` из `tests/browser-fixture.ts`: на Mac каждый тест
  получает свой браузер с закрытием в `finally`, а Linux сохраняет стандартную fixture.
  Одного нового контекста или процесса на файл недостаточно: WebKit удерживает GPU-память
  между тестами. Дополнительный контекст создаётся через `context.browser()`, чтобы не
  запускать второй worker browser. Настройки устройства, `test.use()` и артефакты сохраняются.

# Сборка и зависимости — выученные грабли

Перенесено из корневого `CLAUDE.md` 08.09.2026 без изменения текста. Подгружается само, когда правишь файлы из `paths` в шапке; пути в тексте — от корня репозитория.

- ⛔ **`overrides` в package.json не удалять** (добавлено 03.08.2026, пересмотрено 11.09.2026).
  Astro 5.18.2 и astro-compress держат ВНУТРИ себя свои версии пакетов, и верхнее обновление
  их не достаёт: 03.08 `npm ls sharp` показывал 0.35.3 на верхнем уровне и 0.34.5 у обоих.
  Замещено три пакета:
  - `sharp` ^0.35.4 — внутри libheif 1.23.2. Через этот обработчик идут чужие кадры со стока:
    подбор кадров для ленты и статей разбирает их на машине, где запущен, а сборка — ещё раз,
    в том числе на раннере выкладки с ключом SSH. Критическое уведомление Dependabot на пакет
    astro (GHSA-26w7-cxv4-gfx2, «выполнение кода через AVIF») закрывается именно этой версией
    sharp; сама Astro чинит его только в 7.2.8, через две основные версии, поэтому уведомление
    на astro висит по номеру версии до переезда. Вторая линия — проверка подписи файла до
    декодера в обоих загрузчиках кадров (`isPhotoFile` в `scripts/news-photo.mjs`, 11.09.2026).
  - `svgo` ^4.1.0 — обход плагина removeScripts. У нас недостижимо: плагин не включён, SVG свои.
  - `deepmerge-ts` ^8.0.2 — astro-compress и @playform/pipe прибиты к 7.1.5 с переполнением
    стека на циклических объектах. Сливают они только наши настройки, так что недостижимо;
    замещено ради чистого списка уведомлений, вывод сжатия не изменился (проверка ниже).
  Остальные уведомления на astro требуют серверного режима (у нас `output` не задан вовсе),
  островов с `client:*` (0), плавных переходов (0), раскрытия свойств скопом (0) или
  серверных островов (0); esbuild — только dev-сервер на Windows. Снимать замещения можно
  после переезда на Astro ≥ 7.2.8 и свежий astro-compress, сверив `npm ls sharp svgo deepmerge-ts`.
  Проверка 11.09.2026 (sharp 0.35.3 → 0.35.4, libvips 8.18.6): сборка до обновления и сборка
  после, вторая — с пустым запасом картинок. Из 10 666 файлов совпали байт в байт 10 601 —
  все картинки, CSS, JS и SVG. Разошлись 65 страниц и лент, и ровно те же 65 расходятся между
  двумя сборками подряд без всяких правок: случайный номер карты страны, порядок заметок и
  статей с одной датой, время сборки в ленте Дзена.
- ⛔ **Сменил sharp — сверяй перекодированные картинки сборкой с пустым запасом.** Проверки
  заявки берут `node_modules/.astro` из кеша с ключом только по картинкам из src, без
  package-lock: после смены sharp облако показывает СТАРЫЕ перекодировки, а выкладка (её ключ
  с package-lock) перекодирует всё заново — на сайт уехали бы картинки, которых не видела ни
  одна проверка. Локально: сборка до правки, затем `ASTRO_IMAGE_CACHE_DIR=<пустой каталог
  с суффиксом .noindex> npm run build` и сравнение двух dist по файлам.
- ⛔ **Кеш собранного контента переживает правку плагина разметки.** Astro держит
  отрисованные `.md/.mdx` в `.astro/` и `node_modules/.astro`; правка конфигурации
  кеш сбрасывает, правка самого плагина — НЕТ. 13.08.2026 три сборки подряд отдавали
  прошлый HTML, отладочная печать не появлялась вовсе, код был верен. Проверяешь
  плагин — `rm -rf .astro node_modules/.astro` перед сборкой, иначе смотришь на
  прошлый результат и «чинишь» рабочий код.
